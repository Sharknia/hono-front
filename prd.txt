# **Hono Vibe Flutter Application - 제품 요구사항 문서 (PRD)**

- **문서 버전**: 1.0
- **작성일**: 2025-07-20

## 1. 개요

### 1.1. 프로젝트 목표
Hono Vibe API를 사용하는 프론트엔드 애플리케이션을 Flutter 프레임워크를 통해 개발한다. 본 프로젝트는 단일 코드 베이스로 모바일 앱(iOS, Android)과 웹 애플리케이션 환경에 모두 대응하는 것을 목표로 하며, 심플하고 현대적인 디자인의 사용자 경험을 제공한다.

### 1.2. 타겟 플랫폼
- **모바일**: iOS, Android
- **웹**: 최신 버전의 Chrome, Safari, Firefox

### 1.3. 핵심 성공 지표
- 사용자는 플랫폼(웹/앱)에 구애받지 않고 일관된 UI/UX를 경험할 수 있다.
- 회원가입 및 로그인/인증 플로우가 API 명세에 따라 안정적으로 동작한다.
- 모든 페이지는 반응형 디자인 원칙에 따라 다양한 화면 크기에서 올바르게 표시된다.

## 2. 개발 원칙 (Vibe-Driven Development)
본 프로젝트는 다음 5대 원칙을 가드레일 삼아, 빠른 개발 속도와 코드의 직관성을 유지한다.

1.  **UI와 로직의 분리**: UI(View)와 비즈니스 로직(Logic)의 분리라는 대원칙을 반드시 지킨다. 구조는 직관성을 해치지 않는 선에서 점진적으로 발전시킨다.
2.  **중앙 집중식 상태 관리**: 상태는 한 곳에서, 예측 가능하게 관리한다. 상태 관리 솔루션(예: Riverpod)을 일관되게 사용하여 데이터 흐름을 명확히 한다.
3.  **작고 독립적인 위젯**: 위젯은 레고 블록처럼 최대한 작고 독립적으로 분리하여 재사용성과 유지보수성을 극대화한다.
4.  **핵심 로직 우선 테스트**: UI 테스트보다 핵심 비즈니스 로직(인증, 유효성 검사 등)에 대한 단위 테스트를 우선적으로 작성하여 안정성을 확보한다.
5.  **API 오류의 명확한 처리**: API에서 반환되는 모든 오류(4xx, 5xx) 케이스에 대해 사용자에게 적절한 피드백(스낵바, 대화상자 등)을 제공한다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1. 공통 요구사항
- **반응형 UI**: 모든 페이지와 컴포넌트는 모바일과 웹(데스크톱) 화면 크기에 맞춰 레이아웃이 유동적으로 변경되어야 한다.
- **인증 토큰 관리**:
    - 로그인 성공 시 발급되는 `accessToken`과 `refreshToken`을 안전하게 기기에 저장한다. (권장: `flutter_secure_storage`)
    - API 요청 시 `Authorization` 헤더에 `accessToken`을 포함하여 전송한다.
    - `accessToken` 만료(401 Unauthorized) 시 `refreshToken`을 사용하여 자동으로 토큰을 갱신하는 로직을 구현한다.

### 3.2. 회원가입 페이지 (`/register`)
- **UI 컴포넌트**:
    - 이메일 입력 필드
    - 닉네임 입력 필드
    - 비밀번호 입력 필드 (입력 내용 마스킹 처리)
    - 비밀번호 확인 입력 필드 (입력 내용 마스킹 처리)
    - 회원가입 버튼 (기본 상태: 비활성화)
    - "이미 계정이 있으신가요? 로그인" 텍스트 버튼
- **기능 및 로직**:
    1.  **유효성 검사**:
        - **이메일**: 형식(`@`, `.`)을 검증한다.
        - **닉네임**: 입력 값이 변경될 때마다 `GET /api/users/check/nickname/{nickname}` API를 호출하여 중복 여부를 실시간으로 확인하고 결과를 사용자에게 안내한다. 닉네임이 사용 불가능할 경우, 다른 모든 조건이 충족되어도 회원가입 버튼은 비활성화 상태를 유지한다.
        - **비밀번호**: 비밀번호와 비밀번호 확인 필드의 값이 일치하는지 검증한다.
    2.  **회원가입 버튼**: 위의 모든 유효성 검사(이메일 형식, 닉네임 사용 가능, 비밀번호 일치)를 통과했을 때만 활성화된다.
    3.  **API 호출**: 활성화된 버튼 클릭 시 `POST /api/auth/register` API를 호출하여 회원가입을 요청한다.
    4.  **결과 처리**:
        - **성공 (201 Created)**: "회원가입이 완료되었습니다." 스낵바 또는 대화상자를 표시하고, 로그인 페이지로 자동 이동한다.
        - **실패 (400, 409 등)**: API 응답 메시지에 기반하여 "이미 사용 중인 이메일입니다." 등 적절한 오류 메시지를 사용자에게 표시한다.

### 3.3. 로그인 페이지 (`/login`)
- **UI 컴포넌트**:
    - 이메일 입력 필드
    - 비밀번호 입력 필드
    - 자동 로그인 체크박스
    - 로그인 버튼
    - "계정이 없으신가요? 회원가입" 텍스트 버튼
- **기능 및 로직**:
    1.  **API 호출**: 로그인 버튼 클릭 시 `POST /api/auth/login` API를 호출한다.
    2.  **결과 처리**:
        - **성공 (200 OK)**: `accessToken`과 `refreshToken`을 발급받는다.
            - **자동 로그인 체크 시**: `refreshToken`을 영구적으로 기기에 저장한다.
            - **자동 로그인 미체크 시**: `refreshToken`을 세션 기간 동안만 저장한다.
            - 토큰 저장 후, 메인 페이지로 이동한다.
        - **실패 (401 Unauthorized)**: "이메일 또는 비밀번호를 확인해주세요." 메시지를 표시한다.
    3.  **자동 로그인**: 앱 실행 시, 기기에 유효한 `refreshToken`이 저장되어 있다면 토큰 갱신 API(`POST /api/auth/refresh`)를 호출하여 로그인 상태를 복구하고 즉시 메인 페이지로 이동시킨다.

### 3.4. 메인 페이지 (`/`)
- **UI 컴포넌트**:
    - 상단 앱 바 (Header)
    - 앱 바 우측의 설정 아이콘 버튼 (현재는 기능 없음)
    - 빈 페이지 본문
- **기능 및 로직**:
    1.  **접근 제어 (Route Guard)**:
        - 메인 페이지 접근 시, 사용자의 로그인 상태(유효한 `accessToken` 존재 여부)를 확인한다.
        - 로그인 상태가 아닐 경우, 별도의 안내 메시지 없이 즉시 로그인 페이지로 리다이렉트시킨다.
    2.  **헤더**: 페이지 상단에 일관된 디자인의 헤더를 표시한다.

## 4. API 명세 연동
본 프로젝트는 아래 API 엔드포인트를 사용한다.

| 기능 | HTTP Method | Endpoint | 설명 |
| :--- | :--- | :--- | :--- |
| **회원가입** | `POST` | `/api/auth/register` | 신규 사용자를 생성한다. |
| **로그인** | `POST` | `/api/auth/login` | 사용자를 인증하고 토큰을 발급한다. |
| **토큰 갱신** | `POST` | `/api/auth/refresh` | `refreshToken`으로 새 토큰 쌍을 발급한다. |
| **로그아웃** | `POST` | `/api/auth/logout` | `refreshToken`을 무효화한다. (향후 구현) |
| **닉네임 중복 확인** | `GET` | `/api/users/check/nickname/{nickname}` | 닉네임 사용 가능 여부를 확인한다. |
| **이메일 중복 확인** | `GET` | `/api/users/check/email/{email}` | 이메일 사용 가능 여부를 확인한다. (향후 구현) |
| **내 정보 조회** | `GET` | `/api/users/me` | 현재 로그인된 사용자 정보를 가져온다. (향후 구현) |
